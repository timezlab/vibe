# Compile canonical harness content through adapters

**Status:** accepted
**Date:** 2026-07-22
**Deciders:** Liam Lee

## Context

VIBE targets multiple harnesses (Claude Code, Codex, Gemini CLI, Cursor…),
each with its own config format and capability set. Maintaining N hand-written
copies of the same rules/skills/agents guarantees drift — ECC demonstrates
both the value of multi-harness support and the drift risk of hand-maintained
targets.

## Decision

Keep **one canonical representation** of harness content in this repository
and compile it per platform through **adapters**. Each adapter declares:
(a) its write targets (project + global), (b) the transform from canonical
format, and (c) a capability matrix (hooks? skills? memory?) so the UI knows
what must degrade.

Flow: the user ticks platform checkboxes in the Setup wizard →
`.vibe/config.json` records the choice → `vibe sync` (planned) compiles to
each target (`CLAUDE.md`/`.claude/`, `AGENTS.md`, `GEMINI.md`/`.gemini/`,
`.cursor/rules/`…). Generated files carry a "generated by vibe — edit the
source, not this file" header. Merge-sensitive targets (e.g.
`~/.codex/config.toml`) use an add-only strategy with `--dry-run` first
(learned from ECC's `sync-ecc-to-codex.sh`).

Hook logic is written once as shared scripts; a thin adapter translates event
formats per harness (after ECC's `.cursor/hooks/adapter.js`).

Deliberate difference from ECC: target directories are **build artifacts of
`vibe sync`**, never committed/hand-maintained content.

Target priority: Claude Code (full) → `AGENTS.md` (cheapest, read by Codex,
Gemini, and others) → Cursor when the team needs it.

## Alternatives considered

- **Hand-maintained per-platform copies (ECC's model)** — rejected: drift is
  structural, not accidental; every edit must be repeated N times.
- **Claude-only permanent format** — rejected: locks the org into one harness;
  the `AGENTS.md` target is nearly free and covers several tools at once.

## Consequences

**Better:**

- One edit propagates everywhere; drift becomes impossible by construction.
- The capability matrix makes platform gaps explicit instead of silent.

**Worse:**

- An adapter layer must be designed, tested, and versioned before any
  multi-platform benefit appears.
- Debugging happens in generated output one step removed from what the user
  edited.

**Must now be true:**

- Generated targets carry the generated-file warning header; hand edits to
  them are bugs.
- Merge-sensitive global configs are only ever modified add-only and
  preview-first (`--dry-run`).
- Hook logic lives in shared scripts; per-harness adapters only translate
  event formats.

## Revisit if

A target platform's format churns so fast that adapter maintenance costs more
than a hand-maintained copy, or canonical format expressiveness blocks a
platform capability users need.
