## Dependency direction

```
canonical content  →  adapter transforms  →  generated platform targets
```

Never the reverse: nothing reads from a generated target, and generated
targets are never edited in place
([ADR 0004](docs/decisions/0004-compile-canonical-content-through-adapters.md)).

## Key boundaries

- **Generated artifacts** carry a "generated by vibe" header and are build
  outputs, not maintained content.
- **PTY ownership**: only the Node backend spawns/owns PTY processes; browser
  code talks to them over WebSocket
  ([ADR 0001](docs/decisions/0001-build-vibe-as-a-local-web-app.md)).
- **Git/filesystem mutations** go through application services that resolve an
  explicit, registered target first — worktrees live under
  `<repo>/.vibe/worktrees/<branch>/`
  ([ADR 0002](docs/decisions/0002-use-repository-local-git-worktrees.md)).
- **Memory**: instincts move `pending → approved` only via explicit human
  review (`/instinct-review`); sessions load approved instincts only — the
  loader reads exactly one directory, `.vibe/learned/instincts/approved/`
  ([ADR 0003](docs/decisions/0003-use-reviewed-file-based-memory.md)). The
  per-project store lives at `<repo>/.vibe/learned/` (runtime data, never
  committed — excluded via `.git/info/exclude`), with approved/retired
  instincts mirrored to `~/.local/share/vibe/backup/<project-id>/`.
